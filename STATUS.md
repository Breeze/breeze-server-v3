# breeze-server-v3 — status

Successor to [breeze.server.net](https://github.com/Breeze/breeze.server.net), started
fresh. The old repo is untouched and remains available for 7.x maintenance.

Companion repo: **`breeze-client-v3`**. The client test suite runs against the server here.

## Done

| | old repo | here |
|---|---|---|
| `.csproj` files | 93 | **14** |
| Test databases | 3 | **1** (`BreezeTestDb`) |
| Test data | 40MB of `.mdf`/`.ldf` binaries | **1.5MB SQL script** |
| Target frameworks | net5.0 → net10.0 | **net8.0, net9.0, net10.0** |
| Dead source trees | `AspNet`, `AspNetCore`, `AspNetCore-v3`, `Old` (527 files) | not carried over |

- Layout is `src/` (5 shipping packages), `tests/`, `tools/`.
- `src/Directory.Build.props` holds shared metadata, signing (one `Breeze.snk` instead of
  five copies), packaging and target frameworks. Each `.csproj` is now ~15 lines.
- Root `Directory.Build.props` sets `UseArtifactsOutput`. **Do not remove this.** Two host
  projects (EF Core and NHibernate) share `tests/Test.AspNetCore.EFCore/` and its sources;
  with build output under the project directory each globs the other's generated
  `AssemblyInfo.cs` and the build fails with duplicate assembly attributes. They also must
  not share an `obj/` — a common `project.assets.json` means whichever restored last wins
  and the other loses its package references.
- Version 8.0.0. `GeneratePackageOnBuild` is off; pack explicitly with `dotnet pack`.
- The test server references the **local projects**, not the published 7.5.x NuGet
  packages, so the suite exercises the code in this repo.
- `Breeze.slnx` builds all 14 projects, **0 errors**. The NHibernate host now builds
  alongside the EF Core one, which it could not do in the old layout.
- Fixed two `<see cref="http://...">` XML-doc errors in `NhQueryableInclude.cs`.
- `CS1591` (missing XML comment) is suppressed in `src/Directory.Build.props` — ~546 are
  missing and that is its own task. Other doc warnings stay visible because they indicate
  *malformed* docs. ~52 unique warnings remain, all pre-existing.

## The single test database

`NorthwindIB` + `InheritanceContext` + `ProduceTPH` are consolidated into one database,
**`BreezeTestDb`** (34 tables, no name collisions). `Startup.cs` reads one connection
string.

`InheritanceDbInitializer.Seed` no longer calls `EnsureDeleted`/`EnsureCreated` — on a
shared database that dropped the Northwind and Produce data on every server start. It
clears rows instead.

`tests/Databases/BreezeTestDb.sql` (1.5MB, 33 tables, 235 schema + 4,108 data statements)
replaces the SQL Server 2008-era binaries. It was generated by `tools/DbScripter` and
**verified**: rebuilt into an empty database, row counts identical on every table and
PK/FK/index/trigger/default counts identical. The only difference is `sysdiagrams`, an
SSMS artifact, deliberately excluded.

Because SQL Server creates the database itself, there is no attach step, no file
permission workaround, and no silent v904 → v957 file upgrade.

## Remaining work

- `<Nullable>enable</Nullable>` per project, and delete the now-dead version conditionals.
  There are only **6 preprocessor regions (~30 lines) in 3 files** across 9,735 lines:
  `Breeze.Core/Query/DataType.cs` (2), `Breeze.Core/TypeFns.cs` (1),
  `Breeze.Persistence.EFCore/MetadataBuilder.cs` (3). Dropping net5/6/7 makes every one
  unconditional and deletes the 10-line `MetaTypeEqualityComparer` fallback outright.
- **Add CORS to the test server.** The client suite is moving to Vitest browser mode;
  browser-origin requests to `localhost:34377` will fail without it.
- Seed `UnusualDate.DateOnly` / `TimeOnly`. `Add_DateOnly_TimeOnly.sql` added the columns
  but never populated them, so all 10 rows are NULL and the client's
  `where dateOnly & timeOnly` test cannot pass.
- Retire `tests/Databases/CleanBreezeTestDb.sql`. It cannot restore the database: it
  misses `EmployeeID = 10`, leaves `Customer` at 95 vs 93, and one delete fails with FK
  error `Msg 547`. **Re-applying `BreezeTestDb.sql` is the reliable reset** and takes
  seconds.
- GitHub Actions for build + pack.
- Fix the ~52 malformed XML-doc warnings.

**Newtonsoft.Json stays.** Moving to `System.Text.Json` changes JSON shape at the edges
(`$type`/`$id`, `DateTimeOffset` formatting, dictionary key casing) and the client's
`JsonResultsAdapter` and metadata parser depend on that shape. That is a wire-format
change, not a cleanup, and needs the cross-tier suite as its gate.

## Running it

```bash
dotnet build Breeze.slnx
```

Create the test database:

```bash
sqlcmd -S . -E -Q "CREATE DATABASE BreezeTestDb"
sqlcmd -S . -E -d BreezeTestDb -i tests/Databases/BreezeTestDb.sql
```

Run the server (it reseeds the inheritance tables on startup):

```bash
dotnet run --project tests/Test.AspNetCore.EFCore/Test.AspNetCore.EFCore.csproj \
  --no-launch-profile --urls http://localhost:34377
```

Verify:

```
GET http://localhost:34377/breeze/NorthwindIBModel/Metadata
GET http://localhost:34377/breeze/NorthwindIBModel/Customers
GET http://localhost:34377/breeze/Inheritance/AccountTypes
GET http://localhost:34377/breeze/ProduceTPH/ItemsOfProduce
```

To regenerate the database script from a live database:

```bash
dotnet run --project tools/DbScripter -- tests/Databases/BreezeTestDb.sql
```
