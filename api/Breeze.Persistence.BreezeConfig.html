IncludeLegacyErrorMembers

Whether an error response also carries the pre-3.0 Code, Message and EntityErrors members alongside the RFC 9457 ones.
Default is true, and it costs only a little duplication. RFC 9457 section 3.2 permits extension members and requires consumers to ignore ones they do not recognize, so the response is conformant either way; leaving this on means a breeze-client 2.x or 3.0 application reads errors exactly as it always has, with no coordinated upgrade.
Turn it off once every client is known to read the RFC 9457 members.

public virtual bool IncludeLegacyErrorMembers { get; set; }

Property Value

bool

IncludeStackTraceInErrors

Whether an error response includes the exception's stack trace.
Default is false. A stack trace names source files, line numbers and the directory layout of the machine that built the assembly, so returning it to every caller is an information disclosure. Turn it on deliberately, for development only:

BreezeConfig.Instance.IncludeStackTraceInErrors = env.IsDevelopment();
public virtual bool IncludeStackTraceInErrors { get; set; }

QueryParamName 

Name of query parameter for JSON query string.  Note that this must agree with what the client sends.<br />
Default is null, which means no parameter -- the JSON starts at the question mark: 

?{"take":5}

If non-null, then the JSON is the value of a named parameter.  E.g. if QueryParamName = "bq", then 

?bq={"take":5}
public virtual string? QueryParamName { get; set; }

UseIntEnums

Whether to serialize enum values as string (false) or int (true). Default is false for backward compatibility. Switch to true for more C#-like behavior and see https://github.com/Breeze/breeze.server.net/issues/196 for guidance. Set this value early in startup, because it affects JSON serialization settings and metadata generation.
