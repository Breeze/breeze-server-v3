Remarks

A persistence manager raises this in place of whatever its ORM throws, so that a conflict reaches the client the same way whatever is underneath: EF Core's DbUpdateConcurrencyException and NHibernate's StaleObjectStateException both arrive as 409 Conflict with ProblemTypeUri as the RFC 9457 type.

409 alone is not enough to act on, because a duplicate key is also 409 and the recovery is different - re-read and merge here, change the data there. The type member is what separates them, and it is stable in a way that an ORM's message text is not.

Being an EntityErrorsException, it also carries one EntityError per conflicting row, each naming the entity type and key values. A breeze client turns those into validation errors on exactly the entities that conflicted, which is what lets an application show the user which records to look at rather than failing the whole save with one message.
