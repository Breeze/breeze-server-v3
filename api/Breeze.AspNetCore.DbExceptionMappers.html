Remarks

A duplicate key is a conflict with the current state of the resource, so 409 Conflict says more than a blanket 500 - and unlike a 500, a client will not retry it.

These read the provider's error number off the exception by type name and property, rather than referencing the provider. Breeze supports EF Core, NHibernate and whatever database is behind them, so none of the Breeze packages depends on Microsoft.Data.SqlClient, Npgsql or any other client library, and adding one for this would be the wrong trade. If you would rather match on the concrete type, write the mapping yourself - it is one expression, and StatusCodeForException takes any delegate: 

StatusCodeForException = ex => ex.GetBaseException() is SqlException { Number: 2627 or 2601 or 547 }
  ? HttpStatusCode.Conflict : null

Methods

SqlServer(Exception)

Maps a SQL Server duplicate-key or foreign-key violation to 409 Conflict, and everything else to null, which leaves GlobalExceptionFilter to use its default.

o.Filters.Add(new GlobalExceptionFilter {
  StatusCodeForException = DbExceptionMappers.SqlServer
});

Remarks

Matched on the full type name so that an unrelated exception that happens to have a Number property is not mistaken for one. Both the modern Microsoft.Data.SqlClient and the older System.Data.SqlClient are recognized.
